## Lesson

### 1. A small complete slice is more valuable than many disconnected endpoints.

The core capstone combines a session catalog with persistent student registration; booking rules can remain in a tested CLI. Persistent, concurrent booking is an intermediate outcome.

### 2. A run guide is part of the deliverable.

It states prerequisites, startup order, sample requests, and known limitations. Another person should be able to reproduce results without your terminal history.

### 3. Review one behavior at a time: valid input, invalid input, persistence, and dependency failure.

Keep work visible using a short checklist; use the workshop to repair gaps rather than add new infrastructure.

## Exit check

- Partner can start the project using its guide.
- Persistence and invalid-input behavior are demonstrated.
- Student identifies which code they wrote and which scaffold they used.
